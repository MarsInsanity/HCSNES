# HCSNES 0.4.0 — R36S V2.6 / SF3000

A modified Snes9x 2005 libretro core for TreeFrogUI/PicoArch on MIPS32r2 handhelds.

**Experimental device build.** Both audio variants compile for the handheld.
Native tests pass, including 33,536 Super FX differential cases and full-core
boot/audio/video/state tests. The latest device report identifies a fixed
firmware background-load problem; measurements from before that fix are not
the current baseline. The 0.4 changes still need an on-device comparison.

**New in 0.4.0: stock-like Timed policy and spike diagnostics.** For slow Yoshi's Island gameplay, try
**hcsnes_fast**, **Frameskip = Timed**, **Maximum Consecutive Skips = 3**,
**Profiling = Off**. This skips drawing when a frame starts at least one full
frame late, while advancing emulation and audio on every call. Auto remains
the default. Profiling now records the ten worst frames per window, with GSU
instruction counts and host CPU time to help explain remaining hitches.

Use the [SD-card profiling steps](PROFILING.md) to compare Auto and Timed
without a device shell. See [CHANGELOG.md](CHANGELOG.md) for the changes.

## Source repository

This repository contains the complete emulator source, tests and device tools.
Compiled cores and an `sdcard` directory are generated by the build/package steps;
they are not committed here. Run build commands from the repository root.

## Install on TreeFrogUI

1. Shut down the handheld and put its SD card in your computer.
2. Back up your SNES battery saves and save states.
3. If using a packaged build, copy its **sdcard** contents to the SD-card root.
   If building from this repository, copy **build/sf3000/*_libretro.so** into
   **cubegm/cores**. Optional diagnostic tools and scripts go into **hcsnes**.
4. Start TreeFrogUI. In the regular game browser, highlight Yoshi's Island,
   press **SELECT**, and choose **hcsnes_fast** as the per-game core.
5. Start the game normally. Do not resume a state from another core or audio
   variant. Fast and Plus state formats are different.
6. In PicoArch's core options, start with **Frameskip = Auto** and
   **Maximum Consecutive Skips = 1**. Leave emulated CPU overclocking and
   sprite-limit removal disabled.

If the legacy audio build has sound or compatibility problems, select
**hcsnes_plus** instead.

If Auto does not help, try **Frameskip = Timed**, cap **3**. Timed follows the
game's advertised frame rate without audio-buffer feedback, allows at most three
consecutive skips, and starts fresh after a pause longer than 100 ms. It does
not pace the frontend or sleep; the frontend still controls when frames run.

**Frameskip = Fixed**, cap **1**, is a useful comparison. This renders every
second frame, approximately 30 displayed FPS for an NTSC game, while executing
every emulated frame and generating sound. It reduces PPU rendering cost;
Super FX emulation still runs. Cap 2 means roughly 20 displayed FPS.
Avoid stacking a second frontend frame-skip setting.

The inspected TreeFrogUI version discovers additional *_libretro.so files.
If your version does not list them, power off and add one line to
**frogui/core_overrides.txt**, preserving other lines:

    /mnt/sdcard/ROMS/snes/Your Exact Filename.sfc|/mnt/sdcard/cubegm/cores/hcsnes_fast_libretro.so

Use the actual on-device ROM path and capitalization. A device-shell launcher
is also included. To roll back, select **Default (auto)** for that game.
Existing emulator binaries and firmware are unchanged.

## Included cores

| File | Audio engine | Super FX dispatch | Purpose |
|---|---|---|---|
| hcsnes_fast_libretro.so | Legacy Snes9x APU | Direct threaded | First performance candidate |
| hcsnes_plus_libretro.so | Blargg APU | Direct threaded | Audio/compatibility alternative |
| hcsnes_fast_reference_libretro.so | Legacy Snes9x APU | Original function table | Controlled comparison |

These are complete emulator builds with the inherited CPU, PPU, APU, Super FX,
SA-1 and other supported cartridge hardware. There is no new dynamic recompiler.

## Implemented changes

- **Direct-threaded Super FX:** a generated 1024-entry map replaces the
  per-instruction indirect function call. Existing opcode semantics, budget,
  pipeline, registers and interrupts are retained. PLOT/RPIX use the active mode.
- **Bounded frame skipping:** 0–5 consecutive skips. Auto and Threshold use
  frontend audio feedback. Threshold has a 10-percentage-point recovery margin.
  Fixed mode works without feedback. Timed mode uses a per-frame clock schedule
  and caps consecutive skips at three. Logic, coprocessors and audio run every frame.
- **Option transition fix:** the previous frameskip mode is an unsigned enum
  rather than a boolean, so switching Auto/Threshold reinitializes feedback.
- **MIPS build:** little-endian MIPS32r2, O32, hard float, 32-bit FPU registers,
  PIC, conservative aliasing/overflow flags, and no LTO.
- **RTC fix:** portable 8-byte encoding replaces an upstream 8-byte copy into
  a 4-byte time_t on 32-bit targets.
- **Optional subsystem profiling** with versioned logs, isolated frontend callback timings,
  drawn/skipped core costs, ten worst frames per window, per-frame GSU operation
  counts and optional host thread CPU time. Disabled by default; no save-state layout change.
- **Hidden internal symbol visibility** while preserving exported libretro functions.
- **Tests and device benchmark tools.**

ShallotsOS's corrected device report identifies **one MIPS 74Kc CPU core
online**, with no frequency control. HCSNES uses one emulation thread; the
phrase "direct-threaded" describes opcode dispatch, not multiple CPU threads.
Idle-loop skipping is already enabled by default, with inherited per-game
compatibility exceptions; Yoshi's Island is not on that exception list.

Direct threading changes code size and branch behavior. Its performance is
CPU-dependent: compare with the reference build on your device. Fast versus
Plus also changes audio accuracy; it is not a pure dispatch measurement.

## Measure on the handheld

The headless benchmark excludes SDL display and real audio-device costs.
It reports **emulated FPS separately from rendered FPS**. A headless result
above 100% does not guarantee smooth PicoArch presentation.

With PicoArch closed, from a device shell:

    chmod +x /mnt/sdcard/hcsnes/hcsnes_bench /mnt/sdcard/hcsnes/hcsnes_fx_test
    /mnt/sdcard/hcsnes/hcsnes_fx_test
    sh /mnt/sdcard/hcsnes/diagnose.sh > /mnt/sdcard/hcsnes/device.txt
    sh /mnt/sdcard/hcsnes/benchmark.sh "/mnt/sdcard/ROMS/snes/Your Game.sfc" 3600 > /mnt/sdcard/hcsnes/results.txt 2>&1

Without a state, the benchmark starts from power-on with neutral input. It may
measure an intro instead of demanding gameplay. Supply an **uncompressed raw
libretro state from this build and audio variant** as the third script argument
for a gameplay checkpoint. Fast-reference and Fast share a layout; Plus uses
a separate one. The benchmark warms up for 120 frames after loading.

PicoArch may wrap/compress states. The benchmark rejects an incompatible byte
count. State files also depend on architecture and upstream version.

Also compare the same demanding scene in PicoArch with identical display
settings. Record displayed FPS, audio crackling, and whether controls and game
time run normally. Include the exact core and device information.

**hcsnes-test.sfc** is an original diagnostic ROM. It should show a red backdrop.
It has no gameplay or sound; it only checks loading/rendering.

## Build from included source

Requires Python 3.10+ and Zig **0.13.0** for the supplied Windows/Linux path.
Get Zig from https://ziglang.org/download/0.13.0/ and point --zig at its executable.
The existing GCC/sysroot interface remains supported. Extra `--cflags`,
`--ldflags`, `--output-dir` and `--revision` controls are described in
[PROFILING.md](PROFILING.md).

    # From the repository root (or the ZIP package's source directory):
    python tools/build.py --target sf3000 --apu fast --zig /path/to/zig
    python tools/build.py --target sf3000 --apu plus --zig /path/to/zig
    python tools/build.py --target sf3000 --apu fast --reference --zig /path/to/zig
    python tools/inspect_elf.py build/sf3000/hcsnes_fast_libretro.so
    python tools/run_tests.py --zig /path/to/zig

Outputs are in **build/sf3000**. Native DLL/SO test builds under **build/host**
are not handheld cores. The SF3000 GCC SDK is also supported:

    python tools/build.py --target sf3000 --apu fast --cc /path/to/mips-mti-linux-gnu-gcc --sysroot /path/to/sysroot

**Use tools/build.py.** The retained upstream Makefile does not enable the new
dispatch path or apply this target configuration.

Build the benchmark with:

    zig cc -target mipsel-linux-gnueabihf.2.17 -mcpu=mips32r2 -mabi=32 -mfp32 -O2 -g0 -fno-sanitize=all -Ilibretro-common/include tools/hcsnes_bench.c -ldl -o hcsnes_bench

Build the on-device differential test with:

    zig cc -target mipsel-linux-gnueabihf.2.17 -mcpu=mips32r2 -mabi=32 -mfp32 -O2 -g0 -fwrapv -fno-strict-aliasing -Ilibretro-common/include -DHCSNES_TEST -DHCSNES_THREADED_FX tests/test_fx.c source/fxinst.c source/fxemu.c source/hcsnes_profile.c source/hcsnes_clock.c -o hcsnes_fx_test

GitHub Actions runs native tests and MIPS cross builds on pushes and pull requests.
See the repository Actions tab for the current CI result; **VALIDATION.md** records
the original local validation.

## Validation limits

See **VALIDATION.md**. No commercial ROMs were downloaded or included.
No handheld was attached: runtime loader behavior, controls, actual sound,
0.4 Yoshi's Island speed and broad game compatibility remain untested here.

The Super FX comparisons check equivalence with the inherited interpreter,
not independent accuracy against physical hardware. Full-core host tests use
an original LoROM, not Yoshi's Island, Star Fox or an SA-1 game. No universal
full-speed claim is made.
